# 터치 감지 회로/코드 Before vs Now 비교 (2026-09-10)

`TOUCH_REVIEW.md`의 후속 — 소프트웨어 임계값 변경 및 하드웨어(R13) 변경 이후 현재 상태 정리.

---

## 1. 소프트웨어 — `task_MotorCtrl()` ([main.c:1716](../main.c#L1716))

| 항목 | Before (최초 발견 시) | Now (현재) |
|---|---|---|
| 임계값 | `4095*1/5` = **1V** (819카운트) | `4095*1.5/5` = **1.5V** (1228카운트) |
| `TOUCH_CHECK_WINDOW_MS` | 25ms | **50ms** |
| `TOUCH_CHECK_PERIOD_MS` | 1000ms | 1000ms (동일) |
| Not-Connect 트리거 조건 | `rTouchChattering > 25` | `rTouchChattering > 50` |
| 트리거 후 리셋값 | Not-Connect: 23 / Connect: 15 | 둘 다 **25**로 통일 |
| 윈도우 밖(비활성 975/950ms) 처리 | 없음 (카운터가 윈도우 간 계속 누적) | **매 ms마다 `rTouchChattering = 25`로 강제 리셋 추가** |

**영향**
- 데드존(1V~2V 무반응 구간) 버그는 제가 앞서 고쳐서 현재는 없음 — 1.5V 초과는 전부 Not-Connect로 일관되게 처리됨.
- 윈도우 크기가 25→50ms로 커지면서, 윈도우 밖 강제 리셋이 추가됐음에도 **한 윈도우(50샘플) 안에서 Not-Connect(+26)/Connect(-25) 모두 도달 가능** — 초기엔 "release가 영원히 불가능"으로 잘못 판단했으나 window=50 기준으로는 정정됨.
- 다만 50ms 윈도우가 하필 OUT1/OUT2 노이즈 주기(20Hz≈50ms)와 거의 같아서, 판정이 노이즈 위상에 좌우될 위험은 여전히 남아있음(하드웨어 필터로 해소 예정).

## 2. 하드웨어 — 터치 라인 (R13 풀업)

| 항목 | Before | Now |
|---|---|---|
| R13 구성 | 8.2MΩ 단독 | **8.2MΩ ×2 병렬 = 4.1MΩ** |
| No-touch 실측 전압 | ~1.65V (일부 캡처 ~0.54V) | **1.8V** |
| 역산된 DZ11 등가 누설저항 | ~4.0MΩ | ~2.3MΩ |
| 역산된 DZ11 누설전류 | ~410nA | ~780nA |
| 현재 임계값(1.5V) 대비 마진 | 마이너스(임계값 아래, 오판정) | 약 +0.3V (여전히 근소) |

**영향**
- R13을 절반으로 낮췄지만 전압은 선형 예측(2.47V)만큼 오르지 않음 → **DZ11의 누설전류가 전압에 비례해 함께 증가하는 비선형 특성** 확인됨. 즉 R13만 계속 낮추는 접근은 갈수록 효율이 떨어짐(수확체감).
- 현재 1.8V는 임계값 1.5V를 넘긴 하지만 마진이 작아(~0.3V), 노이즈나 개체편차로 다시 오판정될 위험이 있음.

## 3. 종합 현황 및 다음 액션

| 이슈 | 상태 |
|---|---|
| 데드존 버그 (1V~2V 무반응) | ✅ 수정 완료 |
| Not-Connect 트리거 불가능 여부 | ✅ window=50 기준 정정 — 실제로는 가능 |
| No-touch 전압 마진 부족 | 🔶 개선 중 (1.65V→1.8V), 아직 불충분 |
| DZ11 비선형 누설 | 🔶 확인됨, R13만으로는 한계 — DZ11 교체 검토 필요 |
| 20Hz 스위칭 노이즈 커플링 | ❌ 미해결 — RC 필터(DZ11 병렬 C, 1µF) 미적용 |

**다음 단계 제안**
1. R13을 한 단계 더 낮춰(예: 2.73MΩ 또는 1MΩ) 재측정 → 비선형 곡선 추가 데이터 확보
2. 그래도 마진이 부족하면 DZ11을 누설전류가 더 낮은 부품으로 교체 검토
3. DZ11과 병렬로 1µF 커패시터 추가 → 20Hz 노이즈 필터링 (아직 미적용)
